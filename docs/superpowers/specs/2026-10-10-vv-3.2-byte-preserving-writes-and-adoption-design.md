# vv 3.2 — byte-preserving writes, board affordance, honest adoption measurement

Status: draft for review · 2026-10-10 · supersedes the in-chat draft of the same day after a six-seat panel (Grok, Gemini, Kimi, Codex, Opus, Sonnet) critiqued it. Panel pack and answers: session scratchpad `panel-vv32*` (not committed).

## Problem

1. **Write-safety defect.** Every write path chooses ONE line terminator for the whole file (`src/vv_impl.py` `eol_of`, line 639; `vrust/src/write.rs` `eol_of`, line 63) and `splice` then re-terminates every line with it (`vv_impl.py` 694–697 and the Rust twin). On a note with mixed CRLF/LF endings a one-line `appendsec` rewrote all 438 LF lines to CRLF (measured 2026-10-10 on a throwaway copy; an all-LF control was untouched). The same whole-file choice is used by `append` (EOF branch), `daily-append`, `prepend`, `set`/`unset` (frontmatter rejoin) and `new`.
2. **Local gate red, CI green.** `tests/verify_real_vault.py` "round-trip: every section byte-identical" fails on a live mixed-ending note. The check is an in-process **splice** round-trip (CR-stripped `read` body → `vv.splice` → compare to original bytes), not a `read`-output comparison. CI never fails because the fixture vault contains no mixed-ending note.
3. **`board` affordance.** `vv board F --status open` is refused (8 rows in the 3.1 window); worse, `vv board F --status=open` is **accepted and returns zero rows with exit 0** (verified 2026-10-10) because the filter key becomes `--status`. The refusal's own `next:` hint points at that silent form.
4. **Adoption measurement.** The legacy-logger hook that supplies the adoption denominator was retired on 2026-10-02 by a config-cleanup pass; `bench/pilot_report.py` then printed 100% adoption for every later day. The last valid days (2026-09-23 → 10-02) measured 39–68% against the ≥85% target: the criterion **failed**. The sha8 selector criterion also failed (0 uses).

Resolved during triage, no change needed: the `set` exit 1 seen on the mixed note was the caller passing `probe=1` as one operand (`set` takes `KEY VALUE`); both engines exit 0 with the correct form.

## Goals / non-goals

Goals: a write never changes a byte outside the span it edits; the live-vault gate goes green on the current vault **without weakening the test**; CI can see the mixed-ending class; `board` accepts the flag spelling and never silently matches nothing; adoption reporting fails closed when its denominator is dark; the three high-volume note-editing skills route through vv.

Non-goals (YAGNI, panel-agreed): `read` emitting `\r` (MAJOR, hurts agents; rejected — only the Codex seat proposed it, working without the test source); unifying `set KEY VALUE` with `board KEY=VALUE`; a `--raw` read flag; a `vv doctor` check on `settings.json`; routing `vault-lint`/`metrics` (script-driven report generators); a PreToolUse nudge hook.

## Design

### D1. Line-granular preservation (both engines, one PR)

Mechanism: **keep the existing line model, delete the normalising loop.** `splice` already splits on `\n` only, so every element carries its own `\r` (or none). The defect is the `if crlf:` re-termination pass. Byte-offset splicing was considered and rejected: same guarantee, more parity risk (UTF-8 char vs byte offsets, offsets computed over normalised frontmatter).

Rules for a line vv **creates or changes**:
- Preserved lines are never touched.
- Inserted lines (`appendsec`, `append`, `daily-append`, `prepend`, `set` adding a key) take the terminator of the nearest preserved terminated line **above** the insertion point; if none, the nearest below; if the note has no terminated line, `\n`. Payload `\r\n`/`\n` are normalised to that choice.
- `patch` aligns the CR-stripped old span and new body by common prefix and common suffix; aligned lines keep their original bytes; lines in the changed middle take the terminator of the first changed original line, else the insertion rule. Consequence: `read` → `patch` of an unchanged section is byte-identical on any mix, which is exactly what the live-vault round-trip asserts, so **the test stays as written and goes green**.
- `set`/`unset`: frontmatter becomes a terminator-carrying line list; only the edited key's line is replaced, inserted (after the last key, insertion rule) or removed; `---` delimiters, other keys, BOM and body keep their bytes. Existing refusals (block scalars, etc.) keep their exit codes.
- EOF: unchanged contract — a file that ended with a newline still does, one that did not still does not; an insertion after an unterminated final line gives that line a terminator by the insertion rule (the only pre-existing line that may change, and only by gaining a terminator). `append`'s EOF formula stays, with `eol` = the last real terminator in the file, else `\n`.
- `read` keeps stripping `\r`. sha8 preimage stays what it is today (parity test asserts both engines print the same sha8 for a mixed section; no change to the preimage).

Outcomes: all-CRLF and all-LF notes produce byte-identical output to 3.1; mixed notes change only the created/changed lines; BOM and lone `\r` untouched.

SemVer: MINOR (bug fix; no command, flag, output shape or exit code moves).

### D2. CI sees the class

`.github/workflows/fixture_vault.py` gains notes: all-CRLF, mixed (CRLF block inside LF, and one section internally mixed), no trailing newline in each style, BOM+CRLF, lone `\r` line, frontmatter-LF/body-CRLF. `tests/test_write_parity.py` gains a matrix: every write op × every fixture, both engines byte-identical to each other, every byte outside the edited span identical to the input, and `read`→`patch` unchanged is a no-op. Written first, red on `main`, green after D1 (TDD). Acceptance probe on the real note: `diff -u` of before/after an `appendsec` on a copy shows one `+` line.

### D3. `board` filters

Accept `--KEY VALUE` and `--KEY=VALUE` as aliases of `KEY=VALUE` (strip leading `--` from filter keys) in both engines; global flags are peeled before dispatch, add a reserved-name guard so a future global flag cannot be shadowed. Bare `--KEY`, missing `=`, keep today's refusal, and the `next:` hint echoes the user's own args corrected (`vv board Todos status=open`). `set` untouched. Tests in `test_affordance.py`: three spellings return identical rows on both engines; `--status=open` is no longer empty. SemVer: MINOR (refused input accepted; a wrong answer becomes right; no exit code moves).

### D4. Honest measurement (`bench/pilot_report.py`)

- A measured day with vv note-touch rows and **no legacy rows of any kind** is reported `n/a (denominator dark)` and counted as a failed day in the ≥85% row — never 100%. The table prints how many days were excluded. Unit test on synthetic rows (dark day → excluded; day with only ineligible legacy rows → counted).
- sha8: recorded as **failed at 0** for the 3.1 window; retired from the 3.2 criteria set with the written reason (sha8 is the CAS token `patch` consumes, not a navigation selector; agents address sections by flag/prefix). The selector itself stays. The 3.2 criteria are registered in this spec before the new window opens (below).
- Eligibility audit before the next measure: `Vault Health/` and `Metrics/` paths (script-generated reports) and whole-note creation become non-eligible in `is_eligible_legacy`, so 85% is reachable by construction.

### D5. Release

PR-A: D1 + D2 (fix and tests together, both engines; avoids a red-`main` interval). PR-B: D3. PR-C: D4. PR-D: `release/3.2.0` bumping `VERSION`, `vrust/Cargo.toml` (+lock), `VERSION_FALLBACK`, `CHANGELOG.md`. Each HEAD runs the CI recipe (fixture vault, `env -i`) plus `cargo fmt --check` and `clippy -D warnings`; tag `v3.2.0` on `origin/main` after merge; install; run `./run_tests.sh` once against the live vault and record the result — problem 2 is closed only when that run is green.

### D6. Instrumentation and routing (config plan, separate repo: `~/.claude` and the vault)

- **Re-register the legacy-logger hook now, in parallel with PR-A** (instrumentation is not routing; it also yields a pre-routing 3.1 baseline). Same matcher. Rename script and header to drop the word "pilot" (the cleanup pass read "pilot closed"), and the header names the owner, the decision record id, and the condition for retirement: **a review, not a date** — the hook lives as long as the adoption criterion exists; 2026-10-24 is the review checkpoint, not an auto-retire. Add a daily heartbeat row (`kind: alive`) so "zero legacy rows" is distinguishable from "hook absent". Positive control after registration: one deliberate vault `Read` produces a row.
- **Routing, after 3.2 is installed** (routing writes through vv before D1 would run the corrupting writer more often): `standup` — `outline`/`read SEC` to read, `patch` for section rebuilds, **`daily-append` for one-liners** (it owns the Today-landing rule; `appendsec` would bypass it), `Write` only to create the day's note; `capture-meeting` and `morning-briefing` — lookups via `search`/`board`/`read SEC` **and** writes via `appendsec`/`set`/`daily-append`; whole-note creation stays on `Write`/`vv new`. Not routed: `vault-lint`, `metrics`.
- **Re-measure 2026-10-24** over a window starting at the routing commit, with D4's report. Pre-registered 3.2 criteria: adoption ≥85% on every live-denominator active day; `board` usage rows 0; `read` nonzero-exit <10%; `daily-append` Today landing 100%; write parity matrix green. Outcome recorded in the existing todo; the stale F6 todo is already closed.

## Risks

1. Engine parity drift on the insertion/alignment rules → one shared fixture matrix through both engines in CI (D2), landing in the same PR as the fix.
2. Denominator dies again → heartbeat + fail-closed `n/a` + owner header; a dead hook now makes the report look failed, not perfect.
3. Routing raises `patch` `stale:` exits against Obsidian's own saves and skills fall back to `Write` → measure per-skill exit-3 rate at 2026-10-24; a skill re-`outline`s once and retries rather than falling back.

## Panel record

Six independent plans from one pack; all six verdicts "sound with changes". Adopted from the panel: alignment in `patch` (Opus; Kimi's positional variant), line-level over byte-offset (Kimi/Sonnet/Opus/Codex), fail-closed `n/a` and heartbeat (all), CI fixtures (Opus/Gemini/Codex/Grok), silent `--status=open` bug (Opus, verified), hook restored now and not auto-retired (Opus/Codex/Grok), `daily-append` stays the standup one-liner (Grok), writes not just lookups in capture-meeting/morning-briefing (Grok/Codex), drop "pilot" from the hook's name (Gemini), sha8 recorded failed then retired with reason (Opus/Codex/Sonnet over Kimi's defer). Refuted: "the live suite can only pass by retargeting the test or emitting `\r` from `read`" (Kimi/Sonnet/Grok/Gemini/Codex) — the suite is a splice round-trip, so D1's alignment rule makes it pass unchanged; the pack omitted the test source, which caused the shared error.
